# 履歴閲覧後のグループ画像・動画送信

## 原因

画像・動画の暗号化は `patchGroupKeyLookup` の ID 指定なしの経路からグループ鍵を取得する。
従来は互換キャッシュ `e2eeGroupKeys:<chatMid>` をそのまま使っていたが、この値は履歴の
ID 指定取得や復号準備でも上書きされる。最新鍵を一度準備していても、過去の鍵で送信する
状態になり得た。テキスト送信は送信ごとにサーバーの最新 ID を確認しており、経路が異なる。

## 修正

送信側の ID 指定なし取得では常に `getLastE2EEGroupSharedKey` を呼び、その ID の鍵を
既存のマルチキャッシュから解決する。履歴の ID 指定取得は変更しない。
最新 ID の取得失敗時に古い鍵を採用したり、平文送信へ切り替えたりしない。
画像・動画・その他の暗号化メディアの共通経路を修正し、追加の依存や公開 API は導入しない。

## 検証

`src/login/groupE2EE.test.ts` は実際のスタック暗号化を使用する。変更前は画像・動画とも
最新 ID 91 の代わりに履歴 ID 31 が chunks に入り、4 ケースが失敗した。修正後は以下を確認する。

- 履歴閲覧後の画像・動画が最新鍵 ID を使い、別実装の Letter Sealing 復号で元のペイロードに戻る。
- サーバー上の鍵更新を次回の送信に反映する。
- 最新鍵の取得が拒否された場合はキャッシュへ逃げずに失敗する。
- 履歴は指定した過去の鍵を引き続き取得できる。

```powershell
cd Vyline/packages/protocol
bun test src/login/groupE2EE.test.ts src/e2ee/letterSealing.test.ts stack/base/obs/media_file_e2ee.test.ts stack/base/obs/video_media_e2ee.test.ts
```

修正前の稼働版では、許可済みテストグループへの合成画像・動画の送信と Vyline 内の動画再生は
成功した。一方、ユーザー提供の画像では別グループの画像送信失敗を確認している。
既存サーバーではログを読み取るだけとし、修正版の適用や再起動は行わない。
この修正を適用した環境での再送と正規 LINE クライアントでの再生確認は別途必要。
