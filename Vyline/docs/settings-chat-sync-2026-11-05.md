# 設定・チャット同期・スクロールの修復

最終更新: 2026-11-05

## 概要

設定の表示後にテーマが戻る、未読件数が点滅する、最新送信の本文が古い受信へ戻る、画像が二重に表示される、画像/Flexを含む履歴でスクロールが戻る問題を修正した。画像・動画とファイルの選択ボタンも分離した。

## 前提

- 対象: `tqmane/vyline` main `fa191c0` からの修正。
- 利用者の録画とスクリーンショットは症状の確認に使用した。自動テストは合成データで行い、実アカウントへ接続しない。
- サーバーへの適用・ファイル操作・インストール、ADB/Frida、実メッセージ送信は実施していない。

## 根拠と修正

| 原因 | 修正 |
| --- | --- |
| 設定JSONの遅延読み込みが旧テーマ用ストアを読み込み、hydrate時にCSS変数を上書きしていた | `ThemeApplier`と正本の`useStore.theme`がCSSを管理し、旧バックアップ用ストアのhydrateでCSSを変更しない |
| ローカル既読の保護が60秒だけで、再取得したserver未読件数や過去メッセージを再加算していた | 既読送信ONまたは明示的な手動既読の場合だけ、account/chatごとの既読位置と未反映件数を保存。OFFでは閲覧後もserver未読件数を維持し、新着を加算。serverに反映済みの既読は二重に差し引かず、古い一覧の未読0でも直近の受信を消さない |
| MessageBoxのcursorと本文が別メッセージになり、作成時刻と配信時刻の比較でも古いプレビューが優先されていた | cursorに一致する本文だけを採用。数値メッセージIDを優先し、保存済みの新しいプレビューを一覧応答でも維持 |
| 送信中の仮メディア行と確定行を一部の履歴同期でしか合流していなかった | 差分受信、bootstrap、履歴取得で既存の一対一照合を使用。別の未完了アップロードを残し、置換したBlob URLを解放 |
| 画面上端で切れた画像/Flexをアンカーにすると、後から高さが変わった際にその開始位置へ戻っていた | 次の可視行の開始をアンカーにする。末尾にいる間の高さ変更と新着への追従も維持 |
| classic系の画像用ボタンしかなく、全ファイル選択への独立した導線がなかった | 既存file inputを再利用し、画像・動画とファイルで異なるボタン・アイコン・acceptを指定 |

既読送信OFF（全体・トーク個別）では、開く・閉じる・履歴を読む・再読込だけで未読件数と受信メッセージの既読状態を変更しない。開いている間の新着も未読へ加算する。PR #79で保存された自動ローカル既読位置は、OFF時には無視してserver未読件数を表示する。明示的な「ここまで既読」は手動操作として区別し、既存の送信と件数更新を維持する。別のLINEクライアントで本当に既読になった場合はserverの件数変更を反映する。通話処理は変更しない。

関連する一次資料: waya0125による[未読再加算の修正案](https://github.com/nezumi0627/vyline/pull/397)、[仮想行の高さの修正案](https://github.com/nezumi0627/vyline/pull/394)、[末尾追従の修正案](https://github.com/nezumi0627/vyline/pull/388)。現在の実装との相違を確認し、上記の共通処理へ修正した。

## 検証

```powershell
bun test
bun run typecheck
bun run lint
bun run build
bun Vyline/apps/desktop/tests/theme-persistence.browser.ts
bun Vyline/apps/desktop/tests/receipt-disabled.browser.ts
```

- テーマ: 全5 UIを含む7ケース。設定の遅延読み込み、実reload、カスタムテーマとローカル既読位置の保存、チャットへ戻る操作を確認。
- 画像/ファイル選択・スクロール: 12ブラウザケース。全5 UIで選択・accept切替・異なるアイコンを確認。画像/Flexの高さ変更で約547pxずれた再現が3px未満となり、履歴prependと2〜4ペインも確認。
- 同期: 古い一覧、再読込、全体/個別の既読送信無効、部分既読と未ロード分、server既読反映、旧cursorへの手動既読、メディアの一対一合流をテスト。
- 既読送信OFF: 開閉・履歴同期・reloadで未読13件を維持し、新着で14件へ増える。以前の自動local既読が残っていても未読を隠さず、自動既読APIは0回。手動既読とserver上の実際の既読は別に確認する。
- SQLite: 配信時刻が異なる場合も最新の自送信を維持し、古い一覧で巻き戻らないことを隔離した一時DBで確認。
