# 録音・録画の保存先

## ユーザー要求

2026-09-07追加: Web GUIから保存パスを選択できること。サーバー内の別パス、外部ストレージ、WebDAVに対応する。

## 契約

- 保存先はアカウント別に設定し、録画開始時の保存先を固定する。設定変更で既存ファイルを勝手に移動しない。
- ローカル保存先はサーバーに存在する許可済みのルート内で選ぶ。外部ディスク／ネットワークドライブはサーバーへマウント済みのパスとして扱う。
- Dockerコンテナーの外側の未マウントパス、権限のない場所、ルートを逃げるパス／シンボリックリンクは使用しない。OSマウント・Docker設定・権限をGUIから自動変更しない。
- WebDAVは接続先URL・保存フォルダー・認証情報を設定し、接続状態を確認できる。認証情報は既存の保護方式で保存し、GETやログに実値を返さない。
- URLはHTTPSを基本とし、リダイレクト、認証情報入りURL、メタデータ／ループバック等へのSSRF、DNS再解決による迂回を防ぐ。LAN NASへの接続は利用者が明示した対象に限定する。
- 録画中はサーバーの有界な作業領域へ逐次保存し、完成後にWebDAVへストリーム転送する。転送失敗時はローカルファイルを保持し、再試行とDLを提供する。
- 転送済みを確認するまでローカルの唯一のコピーを削除しない。保存先変更や失敗を成功扱いしない。
- 外部ストレージからの再生・DLも既存認証の内側で配信する。公開共有URLを作らない。
- 削除はその録画が所有するファイルだけを対象とし、既存の外部ファイルを上書き・列挙・一括削除しない。
- 保存先が使用中なら、ファイルを孤立させる接続設定の削除を拒否する。新しい保存先は今後の記録に適用する。

## 実装上の運用条件

### パス候補（2026-09-07追加要求）

- 絶対パス入力に応じて、許可ルートとその直下の実在フォルダーを補完する。ファイル内容、ファイル名、隠しフォルダー、64桁16進数の管理用アカウントディレクトリーは列挙しない。管理用ディレクトリーを直接入力しての候補取得も拒否する。
- `GET /api/line/:accountId/recordings/paths?prefix=...`は既存アカウント認証下の読み取り専用API。`{ok:true, items:string[], truncated:boolean}`。最大20候補・512エントリーの非再帰走査・同時4件とする。
- 許可ルートの外では、ユーザー入力パスをstat/realpath/opendirしない。既存のローカル保存先検証でも先にルート包含を確認し、最大64階層を要素ごとにlstatして、リンクを辿る前に拒否する。解決結果も照合する。許可ルートとその祖先は管理者が管理する安定したファイルシステムを前提とし、敵対的なOSユーザーによる瞬間的な差替えへの完全なrace-safe保証はしない。
- UIは入力の小休止後に取得し、古い入力への応答で候補を上書きしない。候補選択だけでは保存設定を確定せず、既存の追加／保存操作を維持する。
- Dockerではホスト側フォルダーを事前にbind mountし、そのコンテナ側パスを許可ルートへ登録する。GUIから未マウントのホスト全体を参照するためにDocker socketを導入しない。
- 保存先の下にはアカウントIDのSHA-256からなる専用サブフォルダーを自動作成する。2アカウントで同じ保存先を選んでも分離し、同じアカウントの次の記録では同じサブフォルダーを使う。
- 種類は既存テーマのコンパクトな2択（サーバー内／WebDAV）。長い説明を選択肢の外へ分離し、パス候補も同じテーマの一覧から選択できるようにする。

- 許可ルートは`VYLINE_STORAGE_DIR`と`VYLINE_RECORDING_ALLOWED_ROOTS`（OSのパス区切り文字で複数指定）。GUIは既存フォルダーを選択し、Dockerの未マウント領域は利用できない。
- WebDAVにはPROPFIND、MKCOL、PUT、GET/Range、MOVE、DELETEが必要。記録専用partialへPUT→サイズ・SHA-256読戻し→Overwrite:FのMOVE→final読戻しを経てからローカルを除去する。
- WindowsはDPAPI、Linuxは0700フォルダー内の0600 SQLite。Linuxの資格情報・媒体をアプリが保存時暗号化する機能はない。
- WebDAVの接続テストはPROPFINDの読み取り確認であり、書込権限やMOVE対応の完全な保証ではない。
- 詳細なAPI、再試行、期限、認証と既知の制約は[実装仕様](../../docs/call-implementation.md#保存先の運用とwebdavの確定処理)を参照。

## 検証と構造

保存先の解決・所有者・容量・WebDAV転送は `backend/src/storage` に集約し、HTTP入出力はBFF、UIは設定パネルへ配置する。
`bun test`、`bun run typecheck`、`bun run lint`、`bun run build`を用いる。
WebDAVはローカルの隔離テストサーバーで、認証、範囲取得、切断・タイムアウト、再送、上書き防止、保持・削除を検証する。
実NASや第三者の保存先に対する接続テスト・書込みは、利用者が指定した接続先と権限に限定する。
