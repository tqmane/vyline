# 録音・録画とサーバー保存

## 目的・承認内容

個人／グループの音声・ビデオ通話を、明示操作またはユーザーが有効にした自動設定で記録する。
ブラウザーが圧縮し、小さいチャンクでサーバーへ逐次保存する方式は2026-09-07に了承済み。
ブラウザーを閉じた後の無人録画、LINE相手側への録画通知の自動送信、文字起こしは範囲外。

## UI・ライフサイクル

- 初期状態は記録しない。自動設定もOFF。
- 通話画面で「手動／自動」と「録音／録画」を選べる。通話中の選択はその通話だけに適用し、設定画面の既定値を無断で書き換えない。
- 手動停止は即座の自動再開を抑止する。記録種別の変更は記録停止後に行い、進行中ファイルを壊さない。
- 記録開始前に相手の同意が必要なこと、LINE側へ録画表示が自動通知されないことを説明する。
- 録音は通話に送る自分の音声（ミュートを尊重）と受信音声を混合。録画はそれに自分と受信中の映像を合成する。
- 同じ音声・映像接続を再利用し、別のマイク／カメラ取得やLINE再接続を行わない。
- 録画のタイルは固定した出力領域内に配置し、通話UIのスクロールや操作ボタンは記録しない。
- 記録中・送信中・保存済み・中断／失敗を区別し、経過時間はチャンク数から推測しない。
- 手動停止、通話終了、アカウント切替、媒体エラー時は末尾の送信と保存を終えてから解放する。
- 自動設定ONなら接続中に開始する。グループは有効な参加者情報で自分以外の参加を確認してから開始し、自分以外が0人になれば記録だけを停止する。再参加は新しい記録として開始可能。
- 音声から映像への途中切替は既存ファイルを壊さず、必要なら別セグメントとして保存しUIで区別する。
- ページ終了・画面ロック・ブラウザーのバックグラウンド制限では継続を保証しない。途中までサーバーへ届いたデータを中断状態として残し、完全成功と表示しない。

## 保存・API境界

- 既存アカウント認証の内側に配置。開始時はそのアカウントの実在する通話セッションに紐付ける。
- 保存名はサーバー生成ID。外部入力をパスに利用しない。アカウント間の一覧・再生・DL・削除・チャンク書込を遮断する。
- 明示的な開始、順序付きチャンク、終了、一覧／詳細、Range付きファイル取得、削除、保持設定を提供する。
- 小さいチャンクと有界送信待ちを使う。録画全体をRAMに保持せず、ディスクへ追記する。
- 同じチャンクの再送は冪等。順序違い・内容が異なる再送・終了後の追記は拒否する。
- MIME、ヘッダー、サイズ、数値、IDを検証する。鍵、トークン、RTPデータ、実媒体内容はログへ出さない。
- 容量・空きディスク不足では既存データを削除せず新規記録を停止する。録画容量を設定画面へ表示する。
- 保存期間は30日を初期値とし、無期限も選べる。期限と削除操作を明示し、期限処理と途中記録の回復を提供する。
- 公開リンクや外部アップロードは作らない。認証済みのアカウント所有者だけが取得できる。

## 構造・スタイル・コマンド

`backend/src/call` と `backend/src/storage` が保存・生命周期、`backend/src/api` が認証済みHTTP入出力、
`apps/desktop/src/hooks` がブラウザー媒体の記録、既存CallOverlayが操作を担当する。
型を境界に置き、既存のエラー形式、CSS変数、Bunのテスト／SQLiteとストリーム処理を優先する。

```ts
await appendRecordingChunk(accountId, recordingId, offset, bytes);
// 一致する再送だけを受理し、メタデータとファイルの進捗を照合する。
```

ルートで `bun test`、`bun run typecheck`、`bun run lint`、`bun run build`。
個別テストは新規保存・媒体ユーティリティの隣に置き、既存のBun形式を使う。

## 検証

アカウント分離、パストラバーサル、無効MIME、巨大・順序違いチャンク、再送、並行書込、容量不足、
部分書込／再起動、保持期限・無期限、Range、削除を実ファイル付き隔離テストで検証する。
ブラウザーでは生成した音声・映像で音声ありのファイルを作り、サーバーへ保存し、再生・DL・削除まで確認する。
自動設定OFF／ON、ミュート、最後の相手の退出、アカウント切替、録画終了と通話終了の競合を回帰テストにする。

参照: [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event)、
[Canvas captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream)、
[Web Audio destination](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaStreamDestination)。
