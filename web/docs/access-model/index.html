Security

アクセス制御

listen address、LAN access、owner trust は別の設定です。外から開けるために全部を有効化するのではなく、到達経路と認証境界を先に決めます。

標準 Compose の既定

VYLINE_BIND_ADDRESS=0.0.0.0
VYLINE_LAN_ACCESS=false
VYLINE_TRUST_REMOTE_OWNER=false

0.0.0.0 は host 側で接続を受けられるアドレス範囲を示します。一方、VYLINE_LAN_ACCESS と VYLINE_TRUST_REMOTE_OWNER は Vyline 側の access model に関係します。

同じホストだけで使う

外部端末から接続しないなら、host 側の公開範囲も絞れます。

# .env
VYLINE_BIND_ADDRESS=127.0.0.1
VYLINE_LAN_ACCESS=false
VYLINE_TRUST_REMOTE_OWNER=false

reverse proxy や tunnel が同じ host 上にある場合も、Vyline 自体を loopback に閉じて前段だけを公開する構成を選べます。

LAN から使う

VYLINE_LAN_ACCESS=true は、LAN / subdevice access を使う場合に有効にします。単に browser が TCP 接続できることと、Vyline が remote request をどの権限で扱うかは同じではありません。

LAN は「信頼済み Internet」ではありません

共有 Wi-Fi、ゲスト端末、感染端末があるネットワークでは、LAN 内だから安全とは限りません。host firewall でも到達元を必要な範囲に絞ってください。

VYLINE_TRUST_REMOTE_OWNER

VYLINE_TRUST_REMOTE_OWNER=true は、remote browser を owner として扱うための明示的な bypass です。Tailscale ACL、Cloudflare Access、認証済み reverse proxy などで「Vyline に届く前に利用者を限定できている」構成でのみ検討します。

生の LAN / Internet 公開と組み合わせない

到達経路に認証境界がない状態で remote owner trust を有効にすると、Vyline 側の保護を弱めます。

Internet から使う

ルーターで Vyline の port を直接 forward する構成は避けてください。推奨する順序は次の通りです。

  1. VPN（Tailscale / WireGuard など）で private network に入れる。
  2. または Cloudflare Access + Tunnel のように認証を前段に置く。
  3. reverse proxy を使う場合も HTTPS と認証を用意する。
  4. Vyline、Portainer、Docker socket を同じ認証なし endpoint へ出さない。

構成例は 外部アクセス にまとめています。

公開してはいけないもの

  • .env と access token
  • LINE session / token
  • data/ と storage/ の実データ
  • backup archive
  • E2EE key dump
  • Docker socket

これらを Git、公開ログ、Issue、スクリーンショットへそのまま載せないでください。
