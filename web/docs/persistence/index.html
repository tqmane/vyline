Operations

永続化

Docker container は作り直せます。Vyline の状態は /app/data と /app/storage に分離し、標準 Compose では host 側へ bind mount します。

標準の 2 ディレクトリ

hostcontainer扱うもの
./data/app/dataセッション、設定、アカウント状態、チャット履歴など
./storage/app/storage保存メディアと cache。Dockerfile では cache と saved-media の既定先もここに置く

実際のファイル構成は機能追加で変わり得るため、バックアップでは個別ファイル名を選別せず、この 2 ディレクトリを単位として扱うのが安全です。

container とデータを分ける理由

docker compose pull 後の recreate、Dockerfile の更新、container の削除は通常の更新作業です。アプリ状態まで image layer に置くと、この作業でデータが失われます。標準 Compose はそのために bind mount を使っています。

data/ と storage/ を「古い container の残骸」として消さない

container を削除することと、永続化先を削除することは別操作です。

別ディスクへ移す

  1. Vyline を停止します。
  2. data/ と storage/ を新しい保存先へコピーします。
  3. VYLINE_DATA_PATH と VYLINE_STORAGE_PATH を変更します。
  4. mount と所有権を確認してから起動します。
# .env
VYLINE_DATA_PATH=/srv/vyline/data
VYLINE_STORAGE_PATH=/srv/vyline/storage

bind mount の所有権

host 側の filesystem、過去の container、手動コピーなどで ownership が変わると、保存や復元で permission error が出ます。起動ログを確認し、問題がある場合だけ host 側の owner / group / mount option を調べてください。

ls -ld data storage
find data storage -maxdepth 2 -type d -print | head

原因を確認せず再帰的な chmod 777 で済ませるのは避けてください。

cache と保存データ

Dockerfile では CDN / icon cache と saved media を /app/storage 以下で分けています。cache は再取得できることがありますが、storage 全体を cache とみなして削除しないでください。

バックアップ

停止中に host 側の 2 ディレクトリをまとめて退避するのが基本です。オンライン中の個別ファイルコピーより、整合性を取りやすくなります。

docker compose stop
tar -czf vyline-backup.tar.gz data storage
docker compose start

更新・復元の詳細は 更新とバックアップ を参照してください。
