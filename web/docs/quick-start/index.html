Getting started

Quick Start

標準の docker-compose.yml と GHCR image を使って起動します。ここではローカルで開けるところまで進めます。

利用前に確認

Vyline は LINE の非公式クライアントです。メインアカウントを含め、利用に伴うアカウント制限やデータ損失のリスクがあります。

必要なもの

  • Docker Engine
  • Docker Compose v2（docker compose が使えること）
  • linux/amd64 または linux/arm64 の 64-bit ホスト
  • 状態を保存するためのディスク領域

Docker の導入方法は OS 側の手順に従ってください。Vyline 用に独自の Docker build は不要です。

起動する

Compose file を取得

mkdir -p vyline && cd vyline
curl -LO https://raw.githubusercontent.com/tqmane/vyline/main/docker-compose.yml

image を取得して起動

docker compose pull
docker compose up -d

既定の image は ghcr.io/tqmane/vyline:latest です。ホストの architecture に応じて amd64 / arm64 が選ばれます。

状態を確認

docker compose ps
docker compose logs --tail=100

Dockerfile には /healthz を使う healthcheck が入っています。コンテナが起動直後なら healthcheck の開始猶予も考慮してください。

ブラウザで開く

http://127.0.0.1:3000

別端末から LAN 経由で開く場合は、先に アクセス制御 を確認してください。

消してはいけないディレクトリ

標準 Compose はホストの ./data と ./storage をコンテナへ bind mount します。

ホストコンテナ用途
./data/app/dataセッション、設定、履歴などのアプリ状態
./storage/app/storage保存メディアと再取得可能なキャッシュ
更新時に bind mount の中身を削除しないでください

docker compose down やコンテナ再作成自体では、この 2 ディレクトリは削除されません。状態を消す操作は別です。

更新する

docker compose pull
docker compose up -d

docker restart だけでは、新しく pull した image へ切り替わりません。更新時は recreate まで行います。詳しくは 更新とバックアップ を参照してください。

次に確認する

  • 公開ポートや保存先を変える: 設定
  • Raspberry Pi / arm64 SBC: Raspberry Pi / SBC
  • Portainer: Portainer
  • LAN・外部アクセス: アクセス制御 / 外部アクセス
