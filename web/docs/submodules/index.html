Submodules

Vyline は main repository だけで完結していません。LINE protocol、Plugin SDK、Themes、Desktop 解析 tools は Git submodule として固定 commit を参照します。

現在の submodule

pathrepository役割
Vyline/packages/protocoltqmane/vyline-apilogin / transport / RPC / E2EE / OBS / domain facade
Vyline/packages/plugintqmane/vyline-pluginPlugin SDK、permission、examples
Vyline/packages/themestqmane/vyline-themeVyTheme 型と theme presets
toolstqmane/vyline-searchDesktop LINE の version tracking、unpack、xref、decompile 補助

clone

git clone --recurse-submodules https://github.com/tqmane/vyline.git
cd vyline

既存 clone で submodule が空の場合:

git submodule update --init --recursive

現在 main repository が参照している commit は次で確認できます。

git submodule status

「submodule の main」と「Vyline が使う version」は別

submodule は URL だけでなく commit SHA を main repository 側に記録します。submodule repository の main が更新されても、Vyline 側の pointer を更新しない限り checkout 内容は変わりません。

実装確認では pointer の commit を見る

GitHub 上の submodule 最新 main だけを見て「Vyline もこの実装を使っている」と判断しないでください。

Workspace package との違い

root package.json は Vyline/packages/* と apps / backend を Bun workspace として扱います。ただし Git submodule かどうかは別の概念です。たとえば @vyline/line-types は workspace package ですが、Vyline/packages/protocol は workspace package であると同時に Git submodule です。

Protocol を調べるとき

Vyline/packages/protocol/src/dictionary/rpcMap.ts の RPC_DICTIONARY を先に見ます。LINE.js の名前、Desktop evidence、stack / domain / backend の対応がまとまっています。通信処理を main repository だけ検索して見つからない場合は、この境界を確認してください。

submodule pointer を更新する場合

対象 submodule で必要な commit を checkout し、main repository 側で submodule path の変更として commit します。pointer 更新は本体側の build / test と一緒に検証してください。

git status
git submodule status
bun run typecheck
bun test
bun run build

開発環境全体の手順は Developer Guide を参照してください。
