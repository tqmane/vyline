Host guide

Linux

Docker Engine と Compose v2 が正常に動く 64-bit Linux ホストなら、Vyline 側の手順は同じです。OS 固有の差分は Docker の導入、service、firewall、MAC の設定にあります。

最初に確認する

uname -m
docker version
docker compose version

uname -m は一般に amd64 環境で x86_64、arm64 環境で aarch64 と表示されます。Vyline の GHCR image は linux/amd64 と linux/arm64 を提供します。

Docker の導入

Docker Engine の導入は Docker 公式のディストリビューション別手順を使ってください。Vyline のために package manager を固定する必要はありません。

Docker Engine installation docs ↗

Vyline の標準手順は Docker 導入後から共通です

Quick Start の Compose file をそのまま使います。Debian 用、Fedora 用といった Vyline 専用 Compose はありません。

再起動後も動かす

標準 Compose の service には restart: unless-stopped が設定されています。ホスト再起動後に自動復帰させるには、Docker daemon 自体が起動する設定も必要です。

# systemd を使う環境の例
sudo systemctl enable --now docker

docker compose up -d

systemd を使わない環境では、その OS の service manager に合わせて Docker daemon を管理してください。

firewall と bind address

標準 Compose の公開形式は次の通りです。

${VYLINE_BIND_ADDRESS:-0.0.0.0}:${VYLINE_PORT:-3000}:3000

同じホストだけから使うなら VYLINE_BIND_ADDRESS=127.0.0.1 にできます。LAN へ出す場合は VYLINE_LAN_ACCESS の意味を確認し、firewall 側でも必要なネットワークだけに絞ってください。

ポートを Internet へ直接公開しない

Vyline には LINE のセッションや履歴があるため、外部アクセスは VPN、Cloudflare Access、認証済み reverse proxy などの境界を前段に置いてください。

SELinux / AppArmor

通常は無効化を前提にしません。bind mount や Docker network が拒否されたときに、OS の audit log を見て原因を確認します。Vyline の標準コンテナは Dockerfile で /app/data と /app/storage を永続化先として定義しています。

保存先

履歴やメディアが増えるため、空き容量と I/O は CPU より先に問題になることがあります。標準は Compose file と同じディレクトリに data/ と storage/ を作ります。

du -sh data storage
df -h .

別ディスクへ置く場合は 設定 の VYLINE_DATA_PATH / VYLINE_STORAGE_PATH を使います。

Docker を使わない Linux package

リポジトリには installer/install-linux.sh もあります。これは配布物の Vyline 実行ファイルを ~/.local/opt/vyline に配置し、~/.local/bin/vyline と desktop entry を作る installer です。サーバーとしてセルフホストする手順とは別物です。
