Development

Developer Guide

Vyline 本体は Bun workspace です。最初に submodule を含めて clone し、root で一度 install します。Protocol、Plugin、Themes、Tools の境界を無視して main repository だけで完結させないでください。

セットアップ

git clone --recurse-submodules https://github.com/tqmane/vyline.git
cd vyline
bun install --frozen-lockfile

Bun 1.4 以降を前提にしています。既存 clone で submodule が空なら:

git submodule update --init --recursive

workspace / submodule の状態に違和感がある場合は、実装を触る前に:

bun run vyl:doctor
git submodule status

開発サーバー

bun run dev            # backend :3001 + frontend :5173
bun run dev:backend
bun run dev:frontend

backend と frontend を別々に install する必要はありません。root workspace の bun install を使います。

基本の検証

bun run typecheck
bun run lint
bun test
bun run build

変更範囲に応じて必要なものを先に回し、最終確認では build まで通します。Docker、実端末、LINE session を使う確認は local build と別の検証レベルです。

コードを探す

Vyline/apps/desktopReact / Vite UI、store、API client、sync hooks
Vyline/backend/src/service/lineService.tsLINE 関連 business logic の中心
Vyline/backend/src/apiHTTP route と validation
Vyline/packages/protocollogin / RPC / E2EE / OBS / domain facade
Vyline/packages/protocol/src/dictionary/rpcMap.tsRPC_DICTIONARY

Protocol 機能を変更する

  1. RPC_DICTIONARY と既存 analysis docs を確認する。
  2. 必要なら Desktop LINE の evidence を vyline-search で取る。
  3. protocol の stack / domain を変更する。
  4. lineService.ts へ business logic を接続する。
  5. HTTP が必要なら backend/src/api に薄い route を追加する。
  6. tests、typecheck、lint、build を実行する。

Desktop 調査には次の入口があります。

bun run vyline:check
bun run vyline:versions
bun run vyline:find-native -- <name>
bun run vyline:delta
bun run vyline:focus-recovered -- <name>

Frontend を変更する

UI の状態は apps/desktop/src/lib/store.ts、LINE API 型から UI 型への変換は lib/mappers.ts、backend client は api/client.ts、同期処理は hooks/useVylineSync.ts を先に確認します。同じデータを component local state に二重管理する前に既存 store を見てください。

この Web Docs を変更する

web/ は checked-in の静的 HTML / CSS / JS です。ページ本文の generator は使いません。

  • 本文: 対応する web/docs/<page>/index.html を直接編集
  • 共通 UI: web/assets/site.css / site.js
  • ページを追加した場合: site.js の navigation / search metadata も更新

文言は README の要約を膨らませるのではなく、Compose、Dockerfile、実コード、submodule の現在値を確認して書きます。

秘密情報

.env、session / token、backup、account DB、data/、storage/、E2EE key dump は commit しません。実データを debug 出力へ追加するときも、公開可能かを先に確認してください。
