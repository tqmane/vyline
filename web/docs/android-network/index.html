Android Network

dockerd が起動しても、Android の netd / policy routing と Docker bridge が噛み合わず、container の外向き通信や published port だけ壊れることがあります。

典型的な症状

  • container から Docker bridge gateway までは見えるが Internet へ出られない
  • IP address 宛ては通るが DNS だけ失敗する
  • -p 3000:3000 が LISTEN しているのに LAN から timeout / reset する
  • Docker network や container の再作成後だけ壊れる

この状態では Vyline の HTTP/API を調べる前に、Docker network を単体で切り分けます。

Vyline を起動する前の最小テスト

docker run --rm hello-world
docker run --rm alpine uname -m
docker run --rm alpine ping -c 1 1.1.1.1
docker run --rm alpine ping -c 1 google.com

ここで outbound network が通らなければ、問題は Vyline より下の層です。

Android policy routing

Android は通常の Linux server より多くの ip rule を持ち、netd が routing policy を管理します。検証環境では Docker bridge から来た packet が期待する main table へ流れず、明示的な rule が必要でした。

ip rule
ip route show table main
ip route get 1.1.1.1

WAN interface 名を wlan0 と決め打ちせず、実機の route から取得します。

IP forwarding

cat /proc/sys/net/ipv4/ip_forward

Docker bridge から外へ forward する構成では 1 が必要です。検証時に一時的に変更する場合は、Android 全体の routing に影響する操作だと理解して行ってください。

legacy iptables と nft のずれ

検証済み Android 環境では Android 側が legacy iptables、Ubuntu/Docker 側ツールが nft 系という組み合わせがありました。その場合、Docker が nft 側へ publish rule を作っても、実際の packet path が legacy 側を通るため host port が機能しないことがあります。

iptables --version
iptables -t nat -S
iptables -S FORWARD

「Docker が DNAT rule を作った」という確認だけで終わらず、Android の実 packet path と同じ backend に rule があるかを見ます。

Android の既存 rule を flush しない

netd の chain / rule 全体を消さないでください

Android の通信、VPN、アプリごとの routing まで壊す可能性があります。完全ガイドの検証構成では専用 chain と専用 ip rule 範囲だけを管理し、Android 側の既存設定を残しています。

bridge ごとに必要になる処理

検証構成では Docker network を列挙し、各 bridge / subnet に対して次を用意しました。

  • bridge から main table を参照する policy rule
  • bridge → WAN の FORWARD
  • WAN → bridge の RELATED,ESTABLISHED return traffic
  • container subnet → WAN の MASQUERADE

Compose が network を作り直すと bridge 名や subnet が変わることがあるため、固定値を永続 script に書く場合は再検出できる設計が必要です。

published port

Android 側の実 packet path に Docker の自動 DNAT が効かない場合は、running container の IP / port を取得して、Android 側で使われている iptables backend に DNAT / FORWARD を追加する必要があります。

container IP は recreate で変わり得ます。固定 IP を前提にせず docker inspect から現在値を取得します。

診断コマンド

# Android root shell
ip rule
ip route show table main
iptables --version
iptables -t nat -S
iptables -S FORWARD

# Docker side
docker network ls
docker network inspect bridge
docker ps
docker inspect <container>

切り分け順

  1. host 自身が Internet へ出られる。
  2. container から IP address へ出られる。
  3. container DNS が通る。
  4. host から container published port へ接続できる。
  5. LAN 端末から host published port へ接続できる。
  6. 最後に Vyline の login / sync を確認する。

一段ずつ通すと、DNS、NAT、routing、Vyline application のどこで止まっているかを分離できます。

完全版

検証構成で使った dedicated chain、policy rule、watcher、Portainer の host network まで含む通し手順は Android 完全構築ガイド にあります。
