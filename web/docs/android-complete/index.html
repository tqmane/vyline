Android host

Android 完全構築ガイド

root 済み arm64 Android を real chroot + Docker host として使い、Vyline を起動するまでの順序をまとめます。端末固有の値より、どの層を先に成立させるかを重視します。

正本: docs/Vyline-Android-Docker-Complete-Guide-ja.md検証例: OnePlus 9 Pro / arm64

通常の Android アプリ導入ではありません

root、kernel config、mount、loop device、iptables を扱います。失敗すると Android 側のネットワークや起動に影響し得るため、検証用または server 用端末を前提にしてください。

完成形

Android OS / vendor kernel
├─ root
├─ Termux
│  ├─ busybox / openssh / tmux
│  └─ Ubuntu rootfs の準備と起動スクリプト
├─ Ubuntu rootfs (real chroot)
│  ├─ dockerd / containerd / runc
│  └─ docker compose
├─ ext4 loop image → /var/lib/docker
└─ Docker
   ├─ vyline → /app/data, /app/storage
   └─ cloudflared (必要な場合だけ)

1. 端末と kernel を確認

uname -a
uname -m
id
getenforce
cat /proc/cgroups
findmnt -t cgroup,cgroup2

aarch64、root、container に必要な namespace / cgroup / seccomp / OverlayFS / veth / bridge / netfilter / ext4 / loop を確認します。CONFIG の具体例は Kernel 要件 を参照してください。

KVM は Vyline には不要です。/dev/kvm の有無で Docker 可否を判断しません。

2. Termux を入口にする

pkg update -y
pkg install -y proot-distro busybox openssh tmux coreutils curl
termux-wake-lock
sshd

Termux は SSH、rootfs の取得、mount / chroot 起動スクリプトの置き場として使います。Docker runtime 自体を proot の syscall emulation 上で動かす構成にはしません。

3. Ubuntu rootfs を取得し real chroot にする

proot-distro install ubuntu

PREFIX=/data/data/com.termux/files/usr
ROOT="$PREFIX/var/lib/proot-distro/containers/ubuntu/rootfs"
BB="$PREFIX/bin/busybox"

runtime では proot-distro login ではなく BusyBox の chroot を使います。

mount を用意

$BB mount --bind "$ROOT" "$ROOT"
$BB mount --make-rslave "$ROOT"

mkdir -p "$ROOT/dev" "$ROOT/proc" "$ROOT/sys" "$ROOT/run"
$BB mount --rbind /dev "$ROOT/dev"
$BB mount --make-rslave "$ROOT/dev"
$BB mount -t proc proc "$ROOT/proc"
$BB mount --rbind /sys "$ROOT/sys"
$BB mount --make-rslave "$ROOT/sys"
$BB mount -t tmpfs -o mode=755,nosuid,nodev tmpfs "$ROOT/run"

単純な chroot で runc が remount / ... invalid argument になる場合は、rootfs 自身の mountpoint と propagation を先に疑います。

4. /var/lib/docker を ext4 に置く

検証環境では Android の F2FS / casefold 上へ Docker overlay2 を直接置くと EINVAL になりました。そこで sparse ext4 image を使います。

su
mkdir -p /data/local/docker-storage
truncate -s 64G /data/local/docker-storage/docker-ext4.img
/system/bin/mke2fs -t ext4 -F /data/local/docker-storage/docker-ext4.img

IMG=/data/local/docker-storage/docker-ext4.img
LOOP=$(/system/bin/losetup -f)
/system/bin/losetup "$LOOP" "$IMG"

mkdir -p "$ROOT/var/lib/docker"
$BB mount -t ext4 -o rw,noatime "$LOOP" "$ROOT/var/lib/docker"

64 GB は検証例です。容量は端末に合わせて決めてください。sparse image でも、実データが増えれば物理使用量は増えます。

$BB chroot "$ROOT" findmnt -T /var/lib/docker

ここで filesystem が ext4 になっていることを確認します。

5. chroot に Docker Engine を入れる

Ubuntu chroot 内に Docker 公式 repository から arm64 の Engine / Compose を入れます。Android の init が PID 1 なので、systemd service 前提にはしません。

mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "storage-driver": "overlay2",
  "exec-opts": ["native.cgroupdriver=cgroupfs"],
  "log-driver": "local"
}
EOF

rm -f /var/run/docker.pid
nohup dockerd >/var/log/dockerd.log 2>&1 </dev/null &

確認:

docker info

検証構成では Storage Driver: overlay2、Cgroup Driver: cgroupfs、Architecture: aarch64 を確認しています。

6. Vyline より先に Docker をテスト

docker run --rm hello-world
docker run --rm alpine uname -m
docker run --rm alpine ping -c 1 1.1.1.1
docker run --rm alpine ping -c 1 google.com
ここまで通ることが前提

container creation、architecture、IP 通信、DNS を分けて確認します。失敗している層を直してから Vyline へ進みます。

7. Android network を補正

Android の netd / policy routing と legacy iptables が Docker の bridge / published port と衝突する場合があります。

ip rule
ip route show table main
iptables --version
iptables -t nat -S
iptables -S FORWARD

既存の Android rule を一括 flush せず、Docker bridge 用の policy rule、FORWARD、MASQUERADE、必要な DNAT だけを専用範囲 / chain で管理します。詳細は Android Network を参照してください。

8. Vyline の永続化先を作る

Ubuntu chroot 内:

mkdir -p /opt/vyline/data
mkdir -p /opt/vyline/storage

現行 image の entrypoint は bind mount の ownership を確認・修正してから unprivileged user で backend を起動します。

9. Vyline を起動

services:
  vyline:
    image: ghcr.io/tqmane/vyline:latest
    pull_policy: always
    platform: linux/arm64
    ports:
      - "3000:3000"
    volumes:
      - /opt/vyline/data:/app/data
      - /opt/vyline/storage:/app/storage
    environment:
      VYLINE_HOST: 0.0.0.0
      PORT: 3000
      VYLINE_DATA_DIR: /app/data
      VYLINE_STORAGE_DIR: /app/storage
      VYLINE_LAN_ACCESS: "false"
      VYLINE_TRUST_REMOTE_OWNER: "false"
      TZ: Asia/Tokyo
    restart: unless-stopped

platform は multi-arch image では必須ではありませんが、arm64 host であることを明示したい場合に使えます。

10. host と LAN を分けて確認

docker ps
docker logs --tail=100 vyline
curl -I http://127.0.0.1:3000

host 自身では開けるのに LAN から開けない場合、Vyline application より published port / Android routing を疑います。

11. 外部アクセスが必要な場合

Android の host-published port 経路を避けるため、cloudflared を Vyline と同じ Docker network に置き、origin を http://vyline:3000 にする構成を取れます。Tunnel token は environment variable で渡し、Compose file や Git に直書きしません。

Access policy を必ず設定し、生 Internet へ :3000 を直接公開しないでください。

12. docker exec が怪しい場合

検証済み real chroot 環境では、container 本体は正常でも docker exec だけ誤った mount namespace を見る現象がありました。docker exec 内で Android の /system や /vendor が見える場合は、その結果を container rootfs の証拠として扱いません。

PID=$(docker inspect -f '{{.State.Pid}}' vyline)
ls -la "/proc/$PID/root/app"

host 固有の namespace 問題で image 標準 healthcheck が成立しない場合は、Android 用 Compose だけで healthcheck を無効化する選択肢があります。

13. 復元後に履歴が消える場合

最初に /app/data の mount と書き込みを確認します。

docker inspect vyline
du -sh /opt/vyline/data /opt/vyline/storage
docker logs vyline

UI 上で一度見えたことと DB に永続化できたことは別です。現行 image は data / storage が書き込めない場合に entrypoint で失敗させる設計です。

14. 更新

docker compose pull
docker compose up -d

Portainer でも同じで、image pull 後に Stack を update / redeploy して container を recreate します。docker restart だけでは新 image に切り替わりません。

15. 自動起動

Termux:Boot、wake lock、端末メーカー側の background restriction を組み合わせますが、設定しただけで reboot 後の自動復帰を保証しないでください。実機を再起動して SSH、dockerd、Vyline まで戻るかを確認します。

Vyline だけなら要らないもの

Cockpit、libvirt、QEMU、LXC、KVM は Android を汎用 server にする場合の追加要素で、Vyline 単体のためには不要です。

最終チェック

  • aarch64 / root / container-capable kernel を確認した
  • real chroot の mount propagation が成立している
  • /var/lib/docker が想定した ext4 上にある
  • hello-world が通る
  • container から IP / DNS の両方が通る
  • host から Vyline :3000 を開ける
  • LAN 利用時は Android routing / DNAT を確認した
  • /app/data / /app/storage が host へ永続化されている
  • 外部公開には VPN または認証レイヤーがある
  • reboot 後の自動復帰を実機で試した
