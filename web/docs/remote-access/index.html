Networking

外部アクセス

Vyline の port を Internet へ直接出すのではなく、VPN か認証レイヤーを前段に置きます。ここでは構成の選び方だけを扱います。

3000/tcp をそのまま port forward しない

Vyline には LINE session、履歴、メディアへ到達できる機能があります。公開 URL を作る前に、誰がそこへ到達できるかを決めてください。

1. VPN / mesh VPN

自分の端末だけから使うなら、Tailscale や WireGuard などで private network を作る構成が単純です。Vyline は private address で待ち受け、VPN に参加した端末からだけアクセスします。

client ── encrypted VPN ── host:3000 ── Vyline

ルーター側で Vyline の port を公開する必要がなく、利用者の範囲を VPN 側で管理できます。

2. Cloudflare Access + Tunnel

ブラウザから domain 名で使いたい場合は、Cloudflare Tunnel で Vyline へ接続し、Access policy を前段に置く構成を取れます。

browser
  ↓ HTTPS
Cloudflare Access
  ↓ Tunnel
http://127.0.0.1:3000
  ↓
Vyline

重要なのは Tunnel を作ることより、Access policy で許可する利用者を限定することです。dashboard の具体的な画面名は変わることがあるため、設定時は Cloudflare の現行ドキュメントも確認してください。

3. 認証済み reverse proxy

Nginx、Caddy などを前段に置く場合は HTTPS と認証を用意し、Vyline 自体は loopback や private network に閉じます。

Internet
  ↓ HTTPS + authentication
reverse proxy
  ↓ http://127.0.0.1:3000
Vyline

WebSocket を使う経路があるため、proxy 側で Upgrade header を落とさない構成にします。

remote owner trust を使う場合

VYLINE_TRUST_REMOTE_OWNER=true は「前段の認証で owner 以外が到達できない」と確認できたときだけ検討します。Tunnel を使っている、HTTPS である、という事実だけでは owner 認証の代わりにはなりません。

詳細は アクセス制御 を参照してください。

公開前チェック

  • Vyline の origin へ Internet から直接到達できない
  • 認証または VPN の利用者が自分の想定どおりに限定されている
  • Portainer と Docker socket を同じ公開経路へ出していない
  • access log に token / session / backup 内容を残していない
  • VYLINE_TRUST_REMOTE_OWNER を理由なく有効にしていない

LAN 内だけなら

LAN で使うだけなら public domain や Tunnel は不要です。ただし VYLINE_LAN_ACCESS と host firewall の設定は必要です。アクセス制御 を先に確認してください。
