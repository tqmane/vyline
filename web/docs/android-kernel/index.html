Android host

Android Kernel 要件

Android 上で Docker を動かす可否は、Docker CLI の導入より先に kernel feature で決まります。Vyline 固有の kernel patch はありません。

確認するカテゴリ

  1. namespaces
  2. cgroups
  3. seccomp
  4. OverlayFS
  5. bridge / veth
  6. netfilter / conntrack / NAT
  7. ext4 / loop device
  8. proc / sysfs / tmpfs / devpts
  9. mount propagation

検証環境で有効だった基礎 CONFIG

CONFIG_NAMESPACES=y
CONFIG_UTS_NS=y
CONFIG_PID_NS=y
CONFIG_NET_NS=y
CONFIG_USER_NS=y

CONFIG_CGROUPS=y
CONFIG_CGROUP_CPUACCT=y
CONFIG_CGROUP_FREEZER=y
CONFIG_CGROUP_SCHED=y
CONFIG_CPUSETS=y
CONFIG_MEMCG=y
CONFIG_MEMCG_SWAP=y
CONFIG_CGROUP_BPF=y

CONFIG_BPF_SYSCALL=y
CONFIG_SECCOMP=y
CONFIG_SECCOMP_FILTER=y

CONFIG_NETFILTER=y
CONFIG_NF_CONNTRACK=y
CONFIG_IP_NF_IPTABLES=y
CONFIG_IP_NF_FILTER=y
CONFIG_IP_NF_NAT=y
CONFIG_IP_NF_TARGET_MASQUERADE=y

CONFIG_BRIDGE=y
CONFIG_VETH=y
CONFIG_OVERLAY_FS=y

これは OnePlus 9 Pro の検証 kernel で確認した一例です。「この一覧が完全一致しない端末は動かない」という compatibility list ではありません。

カスタム kernel で追加を検討する CONFIG

CONFIG_POSIX_MQUEUE=y
CONFIG_IPC_NS=y
CONFIG_CGROUP_PIDS=y
CONFIG_CGROUP_DEVICE=y
CONFIG_FHANDLE=y
CONFIG_NETFILTER_XT_MATCH_ADDRTYPE=y
CONFIG_BRIDGE_NETFILTER=y

特に古い cgroup v1 や LXC まで扱う場合は、Docker 単体より要求が増えます。必要な runtime に合わせて決めてください。

storage 側

完全ガイドの ext4 loop image 構成を使うなら、少なくとも次を確認します。

CONFIG_EXT4_FS=y        # または module
CONFIG_BLK_DEV_LOOP=y   # または module
CONFIG_OVERLAY_FS=y     # または module
CONFIG_PROC_FS=y
CONFIG_SYSFS=y
CONFIG_TMPFS=y
CONFIG_DEVPTS_FS=y

network 側

CONFIG_NET_NS=y
CONFIG_VETH=y
CONFIG_BRIDGE=y
CONFIG_NETFILTER=y
CONFIG_NF_CONNTRACK=y
CONFIG_IP_NF_IPTABLES=y
CONFIG_IP_NF_FILTER=y
CONFIG_IP_NF_NAT=y
CONFIG_IP_NF_TARGET_MASQUERADE=y

Android では kernel config が揃っていても、netd / policy routing / iptables backend の違いで Docker network が壊れることがあります。そこは Android Network で扱います。

Vyline だけなら不要なもの

KVM、VHE、vhost、virtio、vsock は VM 用で、Vyline container には不要です。/dev/kvm が無いことを Vyline の blocker として扱わないでください。

CONFIG_TUN も Vyline container 自体には必須ではありません。VPN など別用途で必要になる場合があります。

実機で確認する

uname -a
uname -m
id
getenforce

cat /proc/cgroups
findmnt -t cgroup,cgroup2
mount | grep -E 'cgroup|cgroup2'

/proc/config.gz がある場合:

zcat /proc/config.gz | grep -E \
'CONFIG_(NAMESPACES|UTS_NS|IPC_NS|PID_NS|NET_NS|USER_NS|CGROUPS|MEMCG|CGROUP_PIDS|CGROUP_DEVICE|SECCOMP|SECCOMP_FILTER|OVERLAY_FS|VETH|BRIDGE|NETFILTER|NF_CONNTRACK|IP_NF_NAT|EXT4_FS|BLK_DEV_LOOP|TUN)='

/proc/config.gz が無い kernel では、build config か IKCONFIG を別途確認します。自前 kernel なら CONFIG_IKCONFIG / CONFIG_IKCONFIG_PROC を有効にしておくと診断しやすくなります。

vendor scheduler は別問題

Qualcomm / vendor Android kernel へ「一般 Linux の Docker 推奨 config」を丸ごと足すのは避けてください。scheduler や vendor patch と競合する設定は、container 機能とは分けて判断します。
