Operations

更新とバックアップ

更新する対象は container image、残す対象は host 側の data と storage です。この2つを混同しなければ、更新手順は単純です。

更新前

重要な更新の前は、現在の bind mount 元を確認してから退避します。

docker compose config
docker compose ps

docker compose stop
tar -czf vyline-backup-$(date +%Y%m%d-%H%M).tar.gz data storage
docker compose start

保存先を VYLINE_DATA_PATH / VYLINE_STORAGE_PATH で変更している場合は、上の data storage ではなく実際の path を退避してください。

Docker Compose で更新

docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=100

pull は image を取得するだけです。稼働中 container を新しい image に切り替えるには up -d で recreate します。

更新後に見るもの

  • container が running / healthy になっているか
  • /healthz の healthcheck が通っているか
  • ログイン状態とアカウント一覧が残っているか
  • 直近のチャット履歴が見えるか
  • メディア保存先が以前と同じ mount か

「更新後に全部消えた」場合は、アプリの migration より先に bind mount 元が変わっていないか確認します。

戻す必要がある場合

利用したい version tag が GHCR に残っている場合は、VYLINE_IMAGE で image を固定して recreate できます。

# .env の例
VYLINE_IMAGE=ghcr.io/tqmane/vyline:<tag>
アプリのデータ形式も確認する

新しい version で保存された data を古い version が読めるとは限りません。rollback 前に更新前 backup を確保しておくのが安全です。

VylineBackup との違い

設定画面の VylineBackup は、Vyline が管理する履歴・メディア等を snapshot / restore する機能です。一方、host 側の data / storage backup は container 運用全体の退避です。

方法用途
VylineBackupVyline 内から選択して snapshot / restore する
host backupsession、設定、DB、保存物を含む稼働環境をまとめて退避する

片方がもう片方を完全に置き換えるものではありません。

host backup から戻す

  1. Vyline container を停止します。
  2. 現在の data / storage を別名で退避します。
  3. backup を元の bind mount path へ展開します。
  4. ownership と mount を確認します。
  5. 起動して logs と UI を確認します。

復元中に既存データへ上書きコピーするより、退避してから directory 単位で戻す方が切り戻しやすくなります。
