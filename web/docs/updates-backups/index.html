Updates & Backups

GHCR imageの更新と、Host側のdata/・storage/のバックアップ手順です。

containerを更新

docker compose pull
docker compose up -d

restart では既存containerが古いimageを参照し続けます。新imageをpullした後にrecreateします。

バックアップ対象

data/     -> account/session/settings/chat DB/restore state
storage/  -> cache/icons/saved media

data/はセッション、設定、チャットDB、バックアップ等を含むため、Host全体の復旧には必須です。保存済みメディアを維持する場合はstorage/も含めます。

VylineBackupとの違い

設定画面のVylineBackupはアプリ内のスナップショット機能です。Docker host自体を復旧するためのdata//storage/バックアップとは用途が異なります。

整合性を優先するバックアップ

docker compose stop
sudo tar -C . -czf vyline-backup-$(date +%F).tar.gz data storage
docker compose start

containerを停止してからコピーすると、チャットDB等の書き込みとHost側コピーが競合するのを避けられます。backup archiveには認証情報が含まれ得るため、保存先の権限も制限してください。

復元後チェック

  1. bind mount先が復元前と同じか確認する。
  2. container logにpermission errorがないか確認する。
  3. ログイン状態と設定を確認する。
  4. チャット履歴と保存メディアを確認する。
  5. container再作成後も状態が残ることを確認する。
