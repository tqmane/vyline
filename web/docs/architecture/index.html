Internals

Architecture

Vyline は browser UI、backend、LINE protocol を分けています。機能を追うときは、HTTP route から service、protocol の順に下りると実装場所を見つけやすくなります。

全体

Browser
  ↓
Vyline/apps/desktop          React + Vite
  ↓ HTTP / WebSocket
Vyline/backend               Hono on Bun
  ├─ api/                    HTTP I/O / validation
  ├─ service/                business logic
  ├─ line/                   session / client management
  └─ storage/                cache / backup / locks / media
  ↓
Vyline/packages/protocol     @vyline/protocol
  ├─ domain/
  ├─ dictionary/
  ├─ login/ / e2ee/ / obs/
  └─ stack/                  Thrift RPC
  ↓
LINE services

レイヤーごとの責務

場所役割
Vyline/apps/desktopReact UI、client-side state、backend client、同期 hooks
Vyline/backend/src/apiHono route。HTTP の入力・出力と validation
Vyline/backend/src/serviceメッセージ、E2EE、メディア、プロフィールなどの business logic
Vyline/backend/src/lineアカウントごとの LINE client / session 管理
Vyline/backend/src/storagecache、feature lock、詳細ログ、backup、保存物
Vyline/packages/protocol/src/domainprofile / chat / contacts / talk の facade
Vyline/packages/protocol/src/dictionaryLINE.js 名、Desktop 証拠、Vyline 実装の対応表
Vyline/packages/protocol/stackTalk 等の Thrift RPC stack

Backend の境界

backend/src/api/line.ts に LINE の処理を詰め込まず、実際の処理は backend/src/service/lineService.ts へ委譲します。新しい HTTP endpoint を追加するときも、route は request / response の境界として薄く保ちます。

LINE session の取得・切替は backend/src/line/clientManager.ts が担当します。複数アカウントの状態を UI や route ごとに個別管理しないための境界です。

Protocol の境界

@vyline/protocol は独立 submodule です。login、device mode、Desktop compatibility、RPC、E2EE、OBS をここへ集め、本体 UI から LINE の wire format を直接触らない構成にしています。

新しい実装では wrapSession(client) から profile / chat / contacts / talk の domain facade を通す経路が基本です。低レベル RPC が必要な既存機能は stack を直接使う箇所も残っています。

例: プロフィール更新

PATCH /line/:id/profile
  ↓
lineService.updateMyProfile
  ↓
wrapSession(client).profile.update
  ↓
Talk RPC
  ↓
LINE server

UI の変更、HTTP contract の変更、LINE RPC の変更を同じファイルで処理しないのがこの構造の目的です。

Storage

container 運用では /app/data と /app/storage を永続化します。保存メディアと再取得できる cache は同じ storage root の中でも別ディレクトリに分けています。詳しくは 永続化 を参照してください。

本体以外の repository

Protocol 以外にも Plugin SDK、Themes、Desktop 解析 tools が submodule です。機能の正本が main repository にないことがあるため、開発時は Submodules も確認してください。

LINE 仕様を追うとき

RPC 名だけで実装場所を推測せず、Vyline/packages/protocol/src/dictionary/rpcMap.ts の RPC_DICTIONARY から Desktop evidence → stack API → domain API → backend API の順に追います。Desktop 更新調査は tools submodule のコマンドを使います。
