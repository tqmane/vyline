Host guide

Raspberry Pi / SBC

Raspberry Pi 専用の Vyline があるわけではありません。64-bit arm64 Linux と Docker が動く SBC なら、通常の Linux ホストと同じ GHCR image と Compose file を使います。

まず architecture を確認

uname -m
docker info --format '{{.Architecture}}'

Vyline が公開している container image は linux/arm64 と linux/amd64 です。Raspberry Pi で使う場合は aarch64 の 64-bit OS を選んでください。32-bit arm/v7 image は標準の対象ではありません。

特定モデル前提ではありません

Pi 3B、Pi 4、Pi 5 といったモデル名で機能を分けていません。実際に効くのは、64-bit OS が動くこと、Docker が使えること、利用量に対してメモリとストレージ I/O に余裕があることです。

Pi 3B 専用の手順ではありません

メモリが少ない機種でも container が起動する場合はありますが、履歴の取り込みやバックアップ復元は一時的に負荷が上がります。モデル名だけで「対応 / 非対応」を決めず、実際のメモリ使用量と I/O を見て判断します。

Docker と Vyline を起動

Docker Engine を導入した後は Quick Start と同じです。

mkdir -p vyline && cd vyline
curl -LO https://raw.githubusercontent.com/tqmane/vyline/main/docker-compose.yml
docker compose pull
docker compose up -d

docker compose ps

メモリを見る

free -h
docker stats --no-stream

swap や zram はメモリ不足時の猶予にはなりますが、RAM と同じ速度にはなりません。復元中に OOM や極端な遅延が出る場合は、swap を増やす前に同時実行している service と保存先の I/O も確認してください。

microSD と外部ストレージ

Vyline は履歴とメディアを継続的に書き込みます。長期運用では、容量だけでなくランダム I/O と書き込み耐久性も重要です。USB SSD などへ永続化先を移す場合は、Compose の host-side path を変更します。

# .env の例
VYLINE_DATA_PATH=/mnt/vyline/data
VYLINE_STORAGE_PATH=/mnt/vyline/storage

移行前に既存の data/ と storage/ を停止状態で退避し、所有権と mount 状態を確認してください。

常時稼働で見る項目

  • 電源不足や undervoltage が出ていないか
  • USB ストレージが再接続されていないか
  • ファイルシステムの空き容量
  • Docker daemon と Vyline container が再起動後に戻るか
  • 温度上昇で throttling していないか

これらは Vyline 固有ではありませんが、SBC をサーバーとして使う場合の障害原因になりやすい部分です。

バックアップ

OS や microSD を再セットアップしても戻せるよう、data/ と storage/ を別媒体へ定期的に退避します。手順は 更新とバックアップ を参照してください。
