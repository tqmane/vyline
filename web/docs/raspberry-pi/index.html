Raspberry Pi

Raspberry Pi OS 64-bitを使うDockerホスト向けの手順です。特定モデル専用ではありません。

OSとアーキテクチャ

Vylineの公開imageにはlinux/arm64があるため、Raspberry Piでは64-bit Raspberry Pi OSを使用します。現在のComposeは32-bit ARM imageを指定していません。

uname -m
# 期待: aarch64

ハードウェア

Vyline側でRaspberry Piのモデル名を判定して機能を変える実装はありません。差が出るのは主にRAM容量、CPU性能、保存先のI/Oです。

条件影響
4GB以上のRAM大きな履歴復元や他containerとの同時稼働で余裕を確保しやすい。
1GB前後のRAM復元・同期時にswapへ逃げやすく、応答が遅くなる場合があります。
microSDDocker layer、DB、cache、mediaの書き込みが同じ媒体に集中します。
USB SSD / USB storage永続データやDocker data-rootを別媒体へ置きやすくなります。

Raspberry Pi OS 64-bit

sudo apt update && sudo apt full-upgrade -y
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker "$USER"
# 再ログイン後
docker run --rm hello-world

これはDocker公式convenience scriptを使う例です。継続運用する場合はDockerのRaspberry Pi OS向けinstall手順と更新方法も確認してください。

ストレージ

data/、storage/、Dockerのlayerには継続的な読み書きがあります。容量の大きい履歴やメディアを扱う場合は、microSDだけでなくUSB SSD等へ永続データを置く構成も検討してください。

df -hT
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS,MODEL

RAMが少ない場合

zramやswapはOOM回避に使えますが、履歴復元などでswap I/Oが増えるとAPIやUIの応答時間も伸びます。1GB級の端末では不要なcontainerを止め、復元時のメモリ使用量とI/Oを確認してください。

Vyline起動

mkdir -p ~/vyline && cd ~/vyline
curl -LO https://raw.githubusercontent.com/tqmane/vyline/main/docker-compose.yml
docker compose pull
docker compose up -d
docker compose logs -f --tail=100

運用確認

  • docker compose psとdocker compose logs --tail=100でcontainer状態を確認。
  • df -hTでdata/ / storage/を置いたfilesystemの空き容量を確認。
  • OSやkernel更新後はDocker daemonとVylineが再起動できることを確認。
  • バックアップは稼働中の同一microSDだけに置かず、別媒体にもコピーする。
