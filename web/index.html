What is here

動く部分を、実装の場所で分けています。

機能名を並べるより、どこが何を担当しているかを見た方が Vyline は分かりやすくなります。

01

メッセージと同期

送受信、既読、履歴取得、送信取消などの LINE 操作は backend の service 層から protocol へ流れます。
Vyline/backend/src/service/lineService.ts

02

E2EE とメディア

Letter Sealing、グループ鍵、OBS の送受信を protocol 側に分離。LINE Desktop の挙動を追いながら更新します。
Vyline/packages/protocol

03

履歴・メディア・復元

セッションや履歴は data、保存メディア等は storage に置き、コンテナとは分離して保持します。VylineBackup と Android バックアップ取り込みも backend 側で扱います。

04

Plugin / Themes / Tools

Protocol、Plugin SDK、テーマ preset、Desktop 解析ツールは独立した submodule。必要な層だけ追える構成です。

Architecture

UI と LINE 通信を直結しない。

ブラウザから LINE までに責務の境界があります。通信仕様の変更を UI に持ち込まず、protocol と service で吸収します。

Browser → Vyline/apps/desktop → Vyline/backend → Vyline/packages/protocol → LINE services Vyline/packages/plugin — plugin SDK / permissions / examples Vyline/packages/themes — VyTheme / presets tools — Desktop version tracking / unpack / xref / decompile
Architecture Protocol / E2EE Submodules
Start

まず Docker で起動。

標準 Compose は GHCR の image を使い、ホスト側の ./data と ./storage を永続化します。

Docker Engine と Docker Compose v2 が使える 64-bit Linux ホストが基本です。Raspberry Pi などの arm64 SBC でも同じ image を使えます。

LAN やインターネットから使う場合は、先に アクセス制御 と 外部アクセス を確認してください。

$ mkdir -p vyline && cd vyline
$ curl -LO https://raw.githubusercontent.com/tqmane/vyline/main/docker-compose.yml
$ docker compose pull
$ docker compose up -d

# http://<host>:3000
