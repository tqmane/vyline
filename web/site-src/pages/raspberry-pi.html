対応条件

Vyline の公開 Docker image には linux/arm64 が含まれます。Raspberry Pi では、64-bit OS で uname -m が aarch64 になっている構成を基準にしてください。

uname -m
docker version
docker compose version

特定の Raspberry Pi モデル専用の実装はありません。性能やメモリ量はモデルごとに異なるため、同じ Compose を使い、ホスト資源だけ個別に見ます。

起動

mkdir -p ~/vyline && cd ~/vyline
curl -LO https://raw.githubusercontent.com/tqmane/vyline/main/docker-compose.yml
docker compose pull
docker compose up -d

arm64 image は manifest から自動選択されるため、通常は platform: の指定は不要です。

小容量メモリ機で見る項目

Raspberry Pi 3B / 3B+ のような 1 GB クラスでは、Vyline だけでなく Docker daemon、OS、他コンテナを含めたメモリ圧迫を先に疑います。端末内で image をビルドせず、公開 image を pull して使う方が負荷を抑えられます。

free -h
docker stats --no-stream
df -h

swap や zram はホスト OS の設定です。必要なら利用してよいですが、速度低下やストレージ書き込みを隠すための設定にはしないでください。OOM が出る場合は、同居サービスの削減やより大きいメモリのホストも検討します。

ストレージ

履歴、バックアップ、保存メディアが増えるため、data と storage の空き容量を監視します。SD カードの書き込み量を減らしたい場合は、USB SSD など別ストレージへ bind mount 先を移せます。

VYLINE_DATA_PATH=/mnt/ssd/vyline/data
VYLINE_STORAGE_PATH=/mnt/ssd/vyline/storage
docker compose up -d

LAN で使う

Pi を常時稼働サーバーにする場合でも、3000/tcp を無条件にインターネット公開しないでください。家庭内だけで使う、VPN を通す、Cloudflare Access 等で認証する、といった到達経路を先に決めます。

問題が起きたら

まず docker compose logs --tail=200 vyline、docker stats --no-stream、df -h を確認します。遅延とメモリ不足は別問題なので、CPU・RAM・ストレージ I/O を分けて見てください。
