残すべき2つのパス

コンテナ内役割
/app/dataアカウント状態、セッション関連状態、設定、チャット DB、復元履歴、バックアップ関連データ
/app/storageCDN / icon cache、保存した画像・動画・音声・ファイルなど

標準 Compose ではそれぞれ ./data、./storage へ bind mount します。

コンテナ更新とデータは別

image を更新したりコンテナを作り直したりしても、bind mount 先を残せばデータは別に保持されます。逆に data / storage の削除や誤った bind mount 先への変更は、空の状態で起動する原因になります。

権限

現行 image は entrypoint の開始時だけ root で動き、/app/data と /app/storage の所有権を bun:bun に整えてから権限を落とします。restore 後に再起動すると状態が消える場合は、まず host 側 bind mount が実際に書き込み可能かを確認します。

docker compose logs --tail=200 vyline
docker compose exec vyline sh -lc 'id; ls -ld /app/data /app/storage'

VylineBackup

Vyline にはトーク履歴・メディアのスナップショットを作成、復元、削除する仕組みがあります。設定のエクスポート/インポートとは用途が異なります。大きな restore は CPU・メモリ・ストレージ I/O を使うため、ホスト資源と空き容量も確認してください。

ホスト側バックアップ

bind mount 全体をファイルバックアップするなら、書き込み中の DB をコピーしないよう Vyline コンテナを停止してから取るのが単純です。

docker compose stop vyline
# data/ と storage/ をホスト側のバックアップ手段で保存
docker compose start vyline

バックアップ先に LINE セッションやメッセージ履歴が含まれる前提で、アクセス権と保管先を決めてください。
