先に到達経路を決める

Vyline はセッションとメッセージデータを扱います。3000/tcp をそのままインターネットへ開ける構成は避け、Vyline に到達する前に利用者を絞ります。

用途構成例Vyline 側
同一 PC127.0.0.1 bindLAN access 不要
家庭内 LANprivate LAN + firewall必要な場合だけ VYLINE_LAN_ACCESS=true
自分の端末間Tailscale / WireGuardVPN 側 ACL と併用
ブラウザから外部利用Cloudflare Tunnel + Access、または認証済み reverse proxy到達経路を保護した上で設定

ローカル専用

VYLINE_BIND_ADDRESS=127.0.0.1
docker compose up -d

これが最も公開面の小さい構成です。

LAN ペアリング

VYLINE_LAN_ACCESS=true は LAN 端末から利用するための Vyline 側機能を有効にします。ホスト firewall やネットワーク ACL の代わりではありません。

VYLINE_TRUST_REMOTE_OWNER

この変数は、リモートブラウザを PC owner として扱う明示的なバイパスです。Tailscale ACL、Cloudflare Access、認証済み reverse proxy など、到達経路そのものを保護済みの場合だけ使います。

VYLINE_TRUST_REMOTE_OWNER=true

生の LAN やインターネットへ開いたポートで有効化しないでください。

公開してはいけないもの

  • 認証なしの Vyline UI / API
  • Portainer 管理画面
  • Docker socket
  • LINE session / token を含むファイル

切り分け

外から繋がらない場合は「Vyline が起動しているか」「ホスト内から 3000/tcp に届くか」「LAN/VPN から届くか」「proxy/Access を通った後だけ失敗するか」の順に境界を狭めます。
