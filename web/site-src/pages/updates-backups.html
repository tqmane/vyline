更新前

まず現在のコンテナと保存先を確認します。

docker compose ps
docker compose images
docker compose config

docker compose config で data / storage の実際の bind mount 先を確認してからバックアップを取ります。

更新

docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=100 vyline

latest は main の container workflow から更新されます。再現性を優先する運用では、利用する tag / sha を VYLINE_IMAGE で固定できます。

ホスト側バックアップ

単純なファイルコピーなら、書き込みを止めてから data と storage を保存します。

docker compose stop vyline
# host backup: data/ storage/
docker compose start vyline

VylineBackup

アプリ内の VylineBackup は、トーク履歴・メディアのスナップショットを扱います。ホスト全体の障害対策とは別物なので、重要な環境では両方を分けて考えます。

復元後の確認

  • 対象アカウントが期待どおり復元されているか
  • 履歴が再読み込み後も残るか
  • メディアの保存先へ書き込めるか
  • docker compose logs に permission error がないか

ロールバック

image だけ戻す場合は、データを消さず VYLINE_IMAGE を以前の tag / sha に戻します。データ形式の変更を伴う場合は、更新前に取得したバックアップを基準に判断してください。
