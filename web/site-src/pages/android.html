通常の Android アプリ導入手順ではありません

Android 端末そのものを Docker ホストにする構成です。root、Docker に必要なカーネル機能、real chroot が前提です。

検証済みリファレンス

リポジトリ内の完全ガイドは OnePlus 9 Pro / Snapdragon 888 / arm64、カスタム Linux 5.4 QGKI 系カーネル、root、Termux、Ubuntu real chroot、Docker の組み合わせを基準にしています。これは対応端末一覧ではなく、切り分け用の既知構成です。

全体構成

Android / arm64
├─ rooted Android + Docker-capable kernel
├─ Termux
├─ Ubuntu rootfs
│  └─ real chroot
├─ Docker Engine
│  └─ /var/lib/docker on ext4
└─ Vyline container
   ├─ /app/data
   └─ /app/storage

proot-distro は rootfs の用意には使えますが、Docker の常用ランタイムは real chroot(2) を前提にしています。

カーネル

Docker CLI が入るだけでは足りません。少なくとも namespaces、cgroups、seccomp、OverlayFS、bridge/veth、netfilter/NAT、ext4、loop device、mount propagation など container runtime が使う機能を確認します。

zcat /proc/config.gz 2>/dev/null | grep -E \
'CONFIG_(NAMESPACES|CGROUPS|SECCOMP|OVERLAY_FS|VETH|BRIDGE|NETFILTER|EXT4_FS)='

端末の kernel config 提供方法は機種・ROMで異なります。完全ガイドには実機で確認した CONFIG 群と切り分け方法があります。

Docker data-root

Android の /data は F2FS + casefold 等の構成になっていることがあり、overlay2 を直接置くと EINVAL になる例があります。検証構成では ext4 loop image 上へ /var/lib/docker を置いています。

ネットワーク

Android の netd / policy routing は一般的な Linux サーバーと挙動が違います。Docker bridge から外への通信と published port を別々に確認します。

docker run --rm busybox nslookup example.com
curl http://127.0.0.1:3000/healthz

SELinux、iptables/nftables、Android 側 routing のどこで落ちているかを切り分けてください。

Vyline

GHCR image は linux/arm64 対応なので、Android 端末内で Vyline 自体をビルドする必要はありません。

docker pull ghcr.io/tqmane/vyline:latest
docker compose up -d
